# ObsiDrive

개인용 Obsidian ↔ Google Drive 동기화 플러그인입니다. 노트뿐 아니라 **Obsidian 설정, 테마, CSS 스니펫, 커뮤니티 플러그인(코드+설정)** 도 동기화합니다.

- 저장 위치: Google Drive의 **숨김 앱 데이터 폴더(`appDataFolder`)**. Drive 웹/앱의 "내 드라이브"에 폴더나 파일이 **보이지 않습니다.**
  이 OAuth 클라이언트만 접근할 수 있고, 권한 범위도 `drive.appdata` 하나뿐이라 Drive의 다른 파일은 읽거나 쓸 수 없습니다.
- 요구 사항: Obsidian **1.13.2 이상** (데스크톱·모바일 모두 지원)
- 사용자가 직접 만든 Google Cloud OAuth 클라이언트를 씁니다(외부 서버 없음).

> remotely-save를 참고해서 설계했지만 코드는 새로 작성했습니다. remotely-save의 Google Drive 구현은 `pro/` 폴더에 있고 PolyForm Strict 라이선스(파생 작업 금지)라서 가져다 쓰지 않았습니다. 또 remotely-save는 `drive.file` 범위와 일반 폴더를 사용하기 때문에 Drive 웹에서 폴더가 보입니다.

## 1. Google Cloud 설정 (처음 한 번)

1. <https://console.cloud.google.com/> 에서 새 프로젝트를 만듭니다(예: `obsidrive`).
2. **API 및 서비스 → 라이브러리**에서 **Google Drive API**를 검색해 **사용**을 누릅니다.
3. **Google 인증 플랫폼(OAuth 동의 화면)** 을 설정합니다.
   - 사용자 유형: **외부(External)**
   - 앱 이름 / 지원 이메일 / 개발자 연락처: 본인 정보
   - **데이터 액세스(범위)**: `https://www.googleapis.com/auth/drive.appdata` 추가 (민감하지 않은 범위)
   - **대상(Audience)**: **앱 게시(Publish app)** 를 눌러 상태를 **프로덕션**으로 바꾸세요.
     ⚠️ "테스트" 상태로 두면 refresh token이 **7일 뒤 만료**되어 매주 다시 로그인해야 합니다.
     `drive.appdata`는 민감하지 않은 범위라 개인용이면 Google 검수 없이 게시할 수 있습니다. 로그인할 때 "확인되지 않은 앱" 경고가 나오면 **고급 → (앱 이름)(으)로 이동**을 누르면 됩니다.
4. **클라이언트 → 클라이언트 만들기**
   - 애플리케이션 유형: **데스크톱 앱(Desktop app)** ← 반드시 이 유형이어야 합니다 (127.0.0.1 루프백 리디렉션 허용).
   - 만들어진 **클라이언트 ID**와 **클라이언트 보안 비밀번호(Client Secret)** 를 복사해 둡니다.

## 2. 플러그인 설치

```bash
npm install
```

```bash
npm run build
```

빌드 결과물 `main.js`, `manifest.json`, `styles.css` 세 파일을 각 기기 볼트의
`<볼트>/.obsidian/plugins/obsidrive/` 폴더에 복사하고, **설정 → 커뮤니티 플러그인**에서 ObsiDrive를 켭니다.
(모바일은 데스크톱에서 먼저 설치한 뒤 볼트 폴더를 iCloud/USB 등으로 한 번 옮기거나, 위 세 파일만 모바일 볼트의 같은 경로에 넣으면 됩니다.)

## 3. 연결

설정 → ObsiDrive:

1. **OAuth Client ID** 입력
2. **OAuth Client Secret**: 시크릿을 새로 만들어 값을 붙여넣습니다. OS 키체인(Obsidian Secret Storage)에 저장되고 `data.json`에는 남지 않습니다.
3. 로그인
   - **데스크톱**: `Google 로그인` → 브라우저에서 계정 선택·허용 → 자동 완료
   - **모바일**: `Google 로그인` → 브라우저에서 허용 → "사이트에 연결할 수 없음" 페이지가 뜨면 **정상**입니다.
     주소창의 URL 전체(`http://127.0.0.1:42813/?state=…&code=…`)를 복사해서 Obsidian 창에 붙여넣으세요.
     (데스크톱에서도 `수동 로그인`으로 같은 방법을 쓸 수 있습니다.)
4. **원격 볼트 이름**을 모든 기기에서 똑같이 맞춥니다(기본값: 볼트 폴더 이름).
5. 처음에는 명령어 팔레트의 **ObsiDrive: 동기화 미리보기**로 어떤 작업이 일어날지 확인한 다음 **지금 동기화**를 실행하세요.

### 권장 순서 (기존 볼트가 이미 여러 기기에 있을 때)

1. 가장 최신인 기기에서 먼저 동기화해서 원격을 채웁니다.
2. 다른 기기에서 미리보기 → 동기화. 내용이 같은 파일은 전송 없이 넘어가고, 내용이 다른 파일은 **충돌 사본**으로 둘 다 보관됩니다(삭제는 일어나지 않음).

## 동작 방식

### 저장 구조
Drive 폴더를 만들지 않고, 볼트 파일 하나당 숨김 폴더의 파일 하나를 둡니다.
파일 이름 = 볼트 기준 경로(`Notes/오늘.md`, `.obsidian/app.json`), 메타데이터(`appProperties`)에 볼트 키·SHA-256 해시·수정 시각·기기 이름을 저장합니다.
폴더 계층이 없어서 폴더 생성 경쟁이나 이동 중 꼬임 같은 문제가 생기지 않습니다.

### 3-way 동기화
각 기기는 "마지막 동기화 직후 상태"(기준 상태)를 `.obsidian/plugins/obsidrive/sync-state.json`에 저장합니다. 동기화할 때 **로컬 / 원격 / 기준** 셋을 비교해서:

| 로컬 | 원격 | 결과 |
|---|---|---|
| 변경 | 그대로 | 업로드 |
| 그대로 | 변경 | 다운로드 |
| 변경 | 변경 (내용 다름) | **충돌 처리** |
| 삭제 | 그대로 | 원격 삭제(보관) |
| 그대로 | 삭제 | 로컬 휴지통으로 |
| 삭제 | 변경 | 다운로드 (**수정이 삭제를 이김**) |
| 변경 | 삭제 | 업로드 (**수정이 삭제를 이김**) |

변경 여부는 수정 시각/크기로 먼저 거르고, 의심되면 **SHA-256 해시로 내용을 비교**합니다. 그래서 파일을 열기만 해서 시각이 바뀐 경우 등은 전송하지 않습니다.

### 충돌 방지·안전장치
- **충돌 시 둘 다 보관**(기본): 내 버전은 `노트 (conflict 2026-10-17 190233 Windows).md`로 옮기고 원격 버전을 원래 이름에 둡니다. 충돌 사본도 동기화되므로 어느 기기에서든 정리하면 됩니다. 설정에서 "최근 수정본 / 항상 로컬 / 항상 원격"으로 바꿀 수 있습니다.
- **설정 폴더 파일**(`.obsidian/…`)은 충돌 사본이 의미가 없어서 기본으로 "더 최근 수정본"을 씁니다.
- **기준 상태가 없으면 절대 삭제하지 않음**: 상태 파일이 깨지거나 사라져도, 원격 볼트 이름을 바꿔도 삭제는 일어나지 않고 업로드/다운로드/충돌 사본만 생깁니다.
- **대량 삭제 보호**: 한 번에 추적 파일의 30%(설정 가능) 넘게, 그리고 5개 넘게 삭제될 예정이면 확인을 받습니다. 자동 동기화는 그냥 멈추고 알림만 띄웁니다.
- **원격 삭제는 소프트 삭제**: 삭제된 파일은 30일(설정 가능) 동안 내용을 보관하고, **원격 휴지통에서 복원** 명령으로 되살릴 수 있습니다. 로컬 삭제는 Obsidian의 "삭제된 파일" 설정(시스템 휴지통/.trash)을 따릅니다.
- **동기화 도중 편집 보호**: 덮어쓰거나 지우기 직전에 로컬 파일을 다시 확인해서, 그 사이에 편집했다면 건너뛰고 다음 동기화에서 처리합니다. 업로드할 때는 읽는 도중 파일이 바뀌지 않았는지 확인합니다.
- **원격 낙관적 동시성 검사**: 원격 파일을 덮어쓰기 직전에 그 사이 다른 기기가 바꾸지 않았는지 해시로 확인합니다.
- **다운로드 무결성 검사**: 받은 내용의 SHA-256이 원격 메타데이터와 다르면 쓰지 않습니다.
- **원격 중복 정리**: 두 기기가 동시에 같은 새 파일을 올렸을 때, 내용이 같으면 하나를 지우고 다르면 충돌 사본으로 이름을 바꿉니다.
- **대소문자 충돌 보호**: Windows/macOS/Android처럼 대소문자를 구분하지 않는 디스크에서 `A.md`와 `a.md`가 서로 덮어쓰지 않게 막습니다. 대소문자만 바꾼 이름 변경은 정상적으로 처리합니다.
- **이름 변경 감지**: 같은 내용의 "삭제 + 생성"은 이름 변경으로 처리해서, 큰 첨부파일을 옮길 때 다시 전송하지 않습니다.
- **재시도**: 429/5xx/속도 제한은 지수 백오프로 재시도하고, 401은 토큰을 갱신해서 다시 시도합니다.
- **상태 저장**: 동기화 중간중간 상태를 저장하고 두 번 써서(tmp → 본 파일) 앱이 강제 종료돼도 다음 동기화에서 이어갑니다.

### 동기화 대상

| 항목 | 경로 | 기본값 |
|---|---|---|
| 노트·첨부파일 | 볼트 전체 (점으로 시작하는 폴더 제외) | 켬 |
| Obsidian 설정 | `.obsidian/*.json` (app, appearance, hotkeys, core-plugins …) | 켬 |
| 테마 | `.obsidian/themes/*/` | 켬 |
| CSS 스니펫 | `.obsidian/snippets/*.css` | 켬 |
| 커뮤니티 플러그인 | `.obsidian/plugins/*/{main.js,manifest.json,styles.css}` + `community-plugins.json` | 켬 |
| 플러그인 설정 | `.obsidian/plugins/*/data.json` | 켬 |
| 워크스페이스 | `workspace.json`, `workspace-mobile.json` | 끔 |

- **ObsiDrive 자신의 폴더는 절대 동기화하지 않습니다**(설정, 토큰 참조, 동기화 상태는 기기마다 따로).
- 기기마다 설정 폴더를 다르게 쓰는 경우(예: 모바일은 `.obsidian-mobile`) 경로가 달라서 서로 섞이지 않습니다.
- 다른 기기에서 설정/플러그인이 바뀌어 내려오면 **"지금 다시 로드"** 버튼이 있는 알림이 뜹니다. Obsidian은 설정을 시작할 때 읽기 때문에 다시 로드해야 적용됩니다.
- 제외 패턴: `Archive/**`, `*.tmp`, `Private/`, `/^Daily\/2020/` 형식.

### 자동 동기화
- Obsidian 시작 시, N분마다(기본 5분), 마지막 편집 후 N초 동안 조용하면(기본 30초), 앱으로 돌아왔을 때, 네트워크가 복구됐을 때.
- 오프라인이면 조용히 건너뜁니다. 동기화는 한 번에 하나만 돌고, 동기화 중 편집이 있었으면 끝난 뒤 다시 예약합니다.

## 참고 / 제한

- 숨김 폴더도 **Drive 저장 용량에 포함**됩니다. 사용량은 설정의 "저장 용량 확인"으로 볼 수 있습니다.
- 숨김 데이터는 Drive 웹 **설정 → 앱 관리 → (앱 이름) → 숨겨진 앱 데이터 삭제**로 지울 수 있습니다. 앱 연결을 끊는 것만으로는 데이터가 지워지지 않습니다.
- 빈 폴더 자체는 동기화하지 않습니다(파일이 있으면 폴더가 생깁니다). 원격 삭제로 비게 된 폴더는 정리합니다.
- 큰 파일은 메모리에 통째로 올립니다. 모바일에서는 "최대 파일 크기"를 적당히(기본 100MB) 유지하세요.
- 암호화는 하지 않습니다(Google 계정 보안에 의존). 이 OAuth 클라이언트 말고는 숨김 폴더에 접근할 수 없습니다.

## 개발

```bash
npm run dev
```

```bash
npm test
```

- `src/sync/planner.ts`: 순수 3-way 계획 함수 (I/O 없음)
- `src/sync/engine.ts`: 실행·안전장치 (LocalFs / RemoteStore / StateStore 인터페이스)
- `src/drive.ts`: Drive v3 클라이언트 (appDataFolder, multipart/resumable 업로드, 재시도)
- `src/auth.ts`: OAuth PKCE (데스크톱 루프백 / 수동 붙여넣기)
- `src/obsidianFs.ts`: Obsidian Vault/Adapter 연동
- `src/filter.ts`: 동기화 대상 판정
- `tests/`: 가짜 Drive·파일시스템으로 두 기기 시나리오 테스트 (충돌, 삭제 vs 수정, 상태 유실, 대량 삭제, 이름 변경, 동기화 중 편집 등)
